The five relationships to memorise
  • digit value = char − x30  (e.g. '7' = x37 → 7)
  • value → digit char = value + x30, then OUT
  • lower → UPPER = char − x20  ('a'→'A')
  • UPPER → lower = char + x20
  • 'A'..'Z' = x41..x5A,  'a'..'z' = x61..x7A,  '0'..'9' = x30..x39

Is this char a digit?

A character c is a decimal digit iff x30 ≤ c ≤ x39. In LC-3: it is not a digit if (c − x30) < 0 OR (c − x39) > 0.

LD  R4, ToD       ; R4 = -x30
ADD R5, R2, R4    ; c - '0'
BRn NOTD          ; below '0'
ADD R5, R5, #-9   ; (c-'0') - 9
BRp NOTD          ; above '9'
; ... here c is a digit
ToD .FILL x-30

Print a single digit

A value 0–9 in a register is printed by adding x30 to turn it into the ASCII code, then OUT. Works for one digit only.

LD  R0, ZERO      ; x30 = '0'
ADD R3, R3, R0    ; count -> ASCII digit
ADD R0, R3, #0
OUT               ; prints the digit
ZERO .FILL x30
Caesar / shift cipher (F2023 Q2) Encryption that "adds 5 to each ASCII value" is just ADD R0, R0, #5 on each loaded character before OUT. Space x20 + 5 = x25 = %; 'T' x54 + 5 = x59 = 'Y'. Any ASCII value is just a number you can do arithmetic on.
.STRINGZ stores one word per character + a \0 S .STRINGZ "Hi" occupies 3 words: 'H'=x48, 'i'=x69, '\0'=x00. This is why the terminating zero counts when you build a symbol table or a stack layout.
