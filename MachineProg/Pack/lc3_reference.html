A  How to Read an Encoding

Every LC-3 instruction is exactly 16 bits. Bits [15:12] are always the opcode (which instruction). The remaining 12 bits are split into fields whose meaning depends on the opcode. Throughout this sheet, PC in bold means the incremented program counter — the address of the next instruction (A+1 while executing the instruction at A).

opcode [15:12] register (3 bits) immediate / offset (signed) fixed bits
Register codes A register field is 3 bits: R0=000, R1=001, R2=010, R3=011, R4=100, R5=101, R6=110, R7=111.
Method — assemble (assembly → machine code)
  1. Look up the opcode bits for the mnemonic.
  2. Fill register fields with their 3-bit codes.
  3. For an immediate form, set the mode bit and write the value as a signed 2's-complement field of the exact width (imm5, offset6, …).
  4. For PC-relative instructions (BR, LD, ST, LEA, …) the stored offset = target − PC where PC is the address of the next instruction.
  5. Group the 16 bits into 4 nibbles → hex.
Method — disassemble (machine code → assembly) Read [15:12] to get the opcode, then slice the remaining fields per the diagram. For PC-relative forms, the referenced address = PC + SEXT(offset). Sign-extend any signed field before using it.

These two methods cover the F2024 Q1 / F2022 Q1 / F2021 Q1 style of question, where you convert between assembly, binary, and hex, and the symbol-table questions where you track addresses line by line.

Operation: if ((n&N) OR (z&Z) OR (p&P)) PC = PC + SEXT(PCoffset9).

DoesLooks at the condition codes set by the last result, and jumps to LABEL if any selected flag (n/z/p in the mnemonic) is set. BR / BRnzp are unconditional.

Exam essentials
  • Flag source: N/Z/P reflect the last value written to a register (by ADD, AND, NOT, LD, LDR, LEA, …).
  • Branch sense ⇄ C condition: when translating to C or drawing a flowchart, ask "which flag values take the branch?" e.g. BRz done after LDR means "stop at the \0" — the zero terminator. BRnz label takes the branch when result ≤ 0.
  • Self-branch LOOP BRnzp LOOP encodes offset −1 = x0FFF (F2024 Q1a).

D  Loads (memory → register)

The four addressing modes at a glance
  • LEA — gives you an address (PC + offset). No memory access.
  • LD — value at PC + offset (one hop).
  • LDR — value at BaseR + offset (register-based; for arrays, strings, stack frames).
  • LDI — value at the address stored at PC + offset (two hops; indirect).

G  Operand Fields & Ranges

Knowing the exact width and range of each field is what lets you assemble correctly and spot illegal instructions. All offsets/immediates are signed two's-complement except trapvect8.

Why ranges matter in the exam A constant that won't fit a field is the trap. ADD R0,R0,#37 (37 > 15) is rejected — and the same logic applies to a branch that is too far to reach in one PCoffset9. The fix is the same family of workarounds: split into steps, or load the value/address from memory.
Register conventions on the runtime stack
  • R6 = SP (stack pointer; the stack grows toward lower addresses).
  • R5 = FP (frame pointer; locals/arguments are read at fixed offsets from R5 via LDR/STR).
  • R7 = return address — set by JSR and TRAP, used by RET. Save it before nested calls.

H  Condition Codes, SEXT & ZEXT

setcc() — the N / Z / P flags

Many instructions end by setting three single-bit flags from the value just written to DR. Exactly one is 1 at a time:

ResultNZP
negative100
zero010
positive001

Flag-setters: ADD, AND, NOT, LD, LDI, LDR, LEA. Stores and control-flow do not set flags — so a BR reads the flags from the most recent arithmetic/load.

SEXT vs ZEXT

SEXT(A) — sign-extend: copy A's top bit leftward to 16 bits, preserving signed value. 110000 → 1111111111110000.

ZEXT(A) — zero-extend: pad with leading zeros. 110000 → 0000000000110000.

Rule of thumbAll signed offsets/immediates use SEXT; only trapvect8 uses ZEXT (it's an unsigned table index).
PC subtlety (gets people every time) For PC-relative addressing, PC means the address of the next instruction. While the CPU executes the instruction at address A, PC already holds A+1. So an offset stored in an instruction at A reaches A + 1 + offset. When computing the offset to assemble, use target − (A + 1).

I  TRAP Service Routines

VectorNameWhat it does
x20GETCRead one key from the keyboard into R0[7:0] (no echo). High bits cleared.
x21OUTPrint the character in R0[7:0] to the console.
x22PUTSPrint a string: one char per word starting at the address in R0, until a x0000 word.
x23INPrint a prompt, read one key, echo it, copy to R0[7:0].
x24PUTSPPrint a packed string: two chars per word (low byte first), until x0000.
x25HALTStop execution and print a message.
I/O recipes seen in the exams
  • Print a fixed string: LEA R0, S then PUTS, with S .STRINGZ "…".
  • Print one digit (0–9): add x30 ('0') to the value to make it ASCII, then OUT.
  • Read a line: loop GETC / getchar() until newline, storing chars (the C string-reader and charNode-list tasks).
  • End: always finish with HALT.

Three idioms to never forget
  • Zero: AND Rx, Rx, #0
  • Negate: NOT Rx, Rx + ADD Rx, Rx, #1
  • Dereference pointer in Rp: LDR Rd, Rp, #0 (read) / STR Rs, Rp, #0 (write)
R7 hazard Both JSR and TRAP overwrite R7 with the return address. If your routine calls a subroutine or uses a TRAP and then needs to RET, save R7 first (push it on the stack) and restore it before returning.
