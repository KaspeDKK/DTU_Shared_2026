LC-3 Projects — Annotated Reference

Seven assignment files building up to an interactive prime-number checker. Each shown with line numbers, register tables, and an explanation of what it does and why.

The big picture

The assignments build one capability at a time, then assemble them into a complete program and refine it. A1 practises loops and condition codes; A2 reads a number from the keyboard; A3 is the primality algorithm; A4 prints the verdict. A5 wires the three useful pieces together; A5_opt1 and A5_opt2 then improve the input handling.

1A1.asm— Counting toward a target 33 lines↑ top

Goal. A minimal loop exercise. It loads two values A and B (with A<B), then walks R0 up from A and R1 down from B one step at a time until they meet, storing the meeting value in C.

RegRole
R0counter rising from A
R1counter falling from B
R2scratch: computes B−A to test the loop

How the loop ends. Each pass does R0++, R1−−, then forms R2 = R1 − R0 using the negate-and-add trick (NOT then ADD #1 makes −R0, then add R1). While that difference is still positive the counters haven't met, so BRnp X repeats; once equal the difference is zero and it falls through to DONE.

Key idea: LC-3 has no subtract or compare instruction. You subtract by negating in two's complement (NOT + ADD #1) and compare by subtracting and reading the condition codes with a BR.
Watch-outs: the result ends in R1. The BRz DONE just before the DONE label is redundant (it falls through anyway). The data words A/B/C sit after TRAP x25 (HALT), which is fine because HALT stops the CPU before it could try to execute data.

2A2.asm— Read a 2-digit number 69 lines↑ top

Goal. The first real subroutine: prompt the user, read two ASCII digits, and combine them into one integer in R0. Called with JSR READS.

RegRole
R0I/O register (chars in, result out)
R1loop counter / first digit value
R2loop-max (holds −9 for the ×10 loop)
R3saved digit / holds −48 to strip ASCII
R4loop-condition scratch
R7return address (saved/restored)

Subroutine discipline. It stores every register it will clobber (R0–R4, R7) into named slots up front and restores them before RET. This matters because JSR overwrites R7 with the return address — an unsaved R7 across a nested call or re-entry would lose the way back. Saving callee state is the convention the later assignments build on.

ASCII to number. Input arrives as ASCII, so '7' is value 55, not 7. Adding −48 (the Asci constant) converts a digit character to its numeric value.

Times-ten by repeated addition. With no multiply instruction, loopA adds the tens digit to itself repeatedly, using R2 = −9 against counter R1 to stop after the right number of adds; then the second digit is read and added on.

Rough edges (left as written): SaveR0 has no .BLKW of its own, so it labels the same word as SaveR1 — they share storage. The BRnzp loopA before the loopA label and BRz nextIn before nextIn are redundant fall-throughs. This is the experimental first attempt; A5's readS is the cleaner descendant.

3A3.asm— Primality test 60 lines↑ top

Goal. Decide whether the number in R0 is prime, returning R0 = 1 (prime) or R0 = 0 (not). This is the algorithmic heart of the project.

RegRole
R0input number; also the 0/1 result
R1working remainder (counts down by the divisor)
R2current divisor, stored as a negative number

Strategy: trial division using only subtraction. A number n is prime if nothing from 2 to n−1 divides it evenly. With no divide/modulo instruction, divisibility is tested by repeated subtraction: subtract the divisor from n repeatedly; landing exactly on zero means it divides evenly (so n is not prime).

  • Small cases first. Subtracting 1 then another 1 checks n = 1 (not prime) and n = 2 (prime) directly.
  • divisorLoop resets the remainder to n and makes the divisor one more negative (it starts at −1, so the first real divisor tested is 2). Adding the divisor to n once detects when the divisor has climbed to n itself — if so, nothing smaller divided it, so it's prime.
  • subtractionLoop keeps adding the negative divisor: positive → keep subtracting; exactly zero → divides evenly → not prime; negative → this divisor doesn't divide evenly, move to the next divisor.
Why the divisor is negative: storing it negative lets every "subtract" be one ADD, and the n/z/p condition codes after each ADD replace the missing compare instruction.
Standalone version ends in HALT, not RET — it was tested alone. In A5 the same routine ends in RET so it can be called.

isPrime
 
    AND R1,R1,#0    ;nulstiller registre

4A4.asm— Print the result 31 lines↑ top

Goal. Turn the 0/1 from the primality test into a readable line: given R0, print the prime or not-prime message.

How it works. ADD R0, R0, #0 re-sets the condition codes from R0's value (the idiom for "test a register"). BRnp prime takes the prime branch when R0 is non-zero; BRz noPrime handles zero. Each branch loads its string address with LEA and falls into the shared end, which calls PUTS to print the string at R0.

RegRole
R0in: 0/1 flag; then reused as the string address for PUTS
Remember: PUTS wants R0 = address of the string; OUT wants R0 = a single character. LEA loads a label's address into a register with no memory access.

5A5.asm— Full program 127 lines↑ top

Goal. The assembled program. MAIN calls the three subroutines in order and loops forever so the user can test number after number:

MAIN:  readS   →   isPrime   →   resultS   →   (repeat)

This is the integration step: the three blocks (A2-style input, A3 primality, A4 output) live in one file, each ending in RET so JSR/RET chains them. All data flows through R0 — the input number out of readS, then 0/1 out of isPrime, consumed by resultS.

readS here

Reads exactly two characters with TRAP x23 (IN), strips ASCII by adding −'0', then forms 10×first + second, the ×10 done with a 9-iteration add loop. Result in R0.

isPrime here

The A3 algorithm verbatim, but ending in RET so control returns to MAIN.

resultS here

Like A4; uses BRp prime (strictly positive), which is safe because isPrime only returns 0 or 1.

Design limit: the two-digit reader is rigid — always wants exactly two keys, no validation. That's what the two optimised versions fix.

6A5_opt1.asm— Optimised: up to 5 digits 132 lines↑ top

What changed vs A5. A cleaner program that accepts a number of any length up to 5 digits ending on Enter, instead of demanding exactly two keypresses.

RegRole in readS
R0char from GETC; final result
R1scratch for the −newline and −'0' constants
R2numeric value of the current digit
R3,R5scratch for the ×10 shift chain
R4running accumulated value
R6remaining digits allowed (starts at 5)

Three real improvements

  • Character loop with echo. GETC + OUT reads and shows one key at a time and compares against NEWLINE (x0A) to detect Enter. The standard "read until newline" pattern.
  • Proper positional math. Each digit does value = value×10 + digit. The ×10 is built from doublings: 2v, 4v, 8v, then 2v+8v = 10v — four adds, no inner loop, scales to any length.
  • Digit budget. R6 counts down from 5 so at most five digits are taken.
Why doublings: ADD Rx,Rx is a left shift (×2). Composing a few reaches ×10 in constant time — the idiomatic way to multiply by a small constant on LC-3.
Still permissive: opt1 doesn't check the keys are 0–9, and a bare Enter isn't rejected. opt2 closes both gaps.

.ORIG   x3000
MAIN
    JSR     readS          ; R0 = typed decimal number
    JSR     isPrime        ; R0 = 1 if prime, 0 if not
    JSR     resultS        ; print result
    BRnzp   MAIN
    
;---------------------------------------
; readS
; reads a decimal number with up to 5 digits
; user types 1..5 digits and presses Enter
; no zero padding needed
; returns number in R0
;---------------------------------------
readS
    LEA     R0, MSG
    PUTS
 
    AND     R4, R4, #0     ; R4 = current value = 0
    AND     R6, R6, #0
    ADD     R6, R6, #5     ; R6 = remaining digits allowed
 
readLoop
    GETC                   ; read one character
    OUT                    ; echo it
 
    ; check if Enter was pressed
    LD      R1, NEWLINE
    NOT     R1, R1
    ADD     R1, R1, #1
    ADD     R1, R0, R1
    BRz     readDone
 
    ; convert ASCII digit to numeric value
    LD      R1, ASCII_ZERO
    NOT     R1, R1
    ADD     R1, R1, #1
    ADD     R2, R0, R1     ; R2 = digit
 
    ; multiply current value by 10
    ADD     R3, R4, R4     ; 2*value
    ADD     R5, R3, R3     ; 4*value
    ADD     R5, R5, R5     ; 8*value
    ADD     R4, R3, R5     ; 10*value
 
    ; add new digit
    ADD     R4, R4, R2
 
    ; one fewer digit remaining
    ADD     R6, R6, #-1
    BRp     readLoop       ; keep going if still room for more digits
 
readDone
    AND     R0, R0, #0
    ADD     R0, R0, R4     ; return value in R0
    RET
 
;---------------------------------------
; isPrime
; inputs -> R0 = number
; outputs -> R0 = 1 if prime, 0 if not
;---------------------------------------
isPrime
    AND     R1, R1, #0
    AND     R2, R2, #0
    AND     R3, R3, #0
 
    ADD     R2, R2, #-1    ; divisor
 
    ADD     R1, R0, R1
 
    ADD     R1, R1, #-1    ; R0 = 1?
    BRz     isNotPrime
 
    ADD     R1, R1, #-1    ; R0 = 2?
    BRz     isPrimeTrue
    BRp     divisorLoop
 
divisorLoop
    AND     R1, R1, #0
    ADD     R1, R0, R1
 
    ADD     R2, R2, #-1    ; increment divisor
 
    ADD     R1, R1, R2     ; divisor >= n?
    BRz     isPrimeTrue
    BRp     subtractionLoop
 
subtractionLoop
    ADD     R1, R1, R2     ; input - divisor
    BRp     subtractionLoop
    BRz     isNotPrime
    BRn     divisorLoop
 
isPrimeTrue
    AND     R0, R0, #0
    ADD     R0, R0, #1
    RET
 
isNotPrime
    AND     R0, R0, #0
    RET
 
;---------------------------------------
; resultS
; prints whether the number is prime
;---------------------------------------
resultS
    ADD     R0, R0, #0
    BRp     primeMsg
    BRz     notPrimeMsg
 
primeMsg
    LEA     R0, stringPrime
    PUTS
    RET
 
notPrimeMsg
    LEA     R0, stringNotPrime
    PUTS
    RET
 
;---------------------------------------
; prints and data
;---------------------------------------
MSG             .STRINGZ "Input a decimal number (up to 5 digits): "
stringPrime     .STRINGZ "\nThe number is prime"
stringNotPrime  .STRINGZ "\nThe number is not prime"
ASCII_ZERO      .FILL   x0030
NEWLINE         .FILL   x000A
 
.END
7A5_opt2.asm— Optimised: with validation 159 lines↑ top

What changed vs opt1. Same fast input engine, now validated — the most defensive version and the natural final submission.

Validation added in readS

  • Too many digits. Before accepting a key it checks R6 − 5; a sixth digit jumps to tooManyDigits, which prints an error and restarts MAIN.
  • Range check per character. After char − '0' into R2, a negative result means the key was below '0' (→ invalidInput); R2 − 10 with BRzp catches keys above '9'. Only true digits pass.
  • Empty input. At checkDone it confirms the digit count is non-zero, rejecting a bare Enter.
RegRole in readS
R0char in / result out
R1scratch for comparisons (−newline, −'0', −10, −5)
R2candidate digit value, range-checked
R3,R5×10 shift scratch
R4accumulated value
R6accepted digit count

isPrime / resultS are unchanged from opt1. The errFormat and errTooLong strings give the two messages, and every error path branches back to MAIN to ask again rather than halting.

Pattern worth keeping: validate as you read and centralise recovery by jumping back to the main loop. By the time readS returns, R0 is guaranteed to hold a clean 1–5 digit number.

.ORIG   x3000
 
MAIN
    JSR     readS          ; R0 = typed decimal number
    JSR     isPrime        ; R0 = 1 if prime, 0 if not
    JSR     resultS        ; print result
    BRnzp   MAIN
 
;---------------------------------------
; readS
; reads a decimal number with 1 to 5 digits
; validates input format
; returns number in R0
; on invalid input prints error message and halts
;---------------------------------------
readS
    LEA     R0, MSG
    PUTS
 
    AND     R4, R4, #0     ; R4 = current value
    AND     R6, R6, #0     ; R6 = digit count
 
readLoop
    GETC
    OUT
 
    ; check for Enter
    LD      R1, NEWLINE
    NOT     R1, R1
    ADD     R1, R1, #1
    ADD     R1, R0, R1
    BRz     checkDone
 
    ; if already 5 digits, any extra char is invalid
    ADD     R1, R6, #-5
    BRzp    tooManyDigits
 
    ; convert ASCII to numeric candidate: char - '0'
    LD      R1, ASCII_ZERO
    NOT     R1, R1
    ADD     R1, R1, #1
    ADD     R2, R0, R1     ; R2 = char - '0'
 
    ; if negative, char was below '0'
    BRn     invalidInput
 
    ; if R2 >= 10, char was above '9'
    ADD     R1, R2, #-10
    BRzp    invalidInput
 
    ; value = value * 10
    ADD     R3, R4, R4     ; 2*value
    ADD     R5, R3, R3     ; 4*value
    ADD     R5, R5, R5     ; 8*value
    ADD     R4, R3, R5     ; 10*value
 
    ; value = value + digit
    ADD     R4, R4, R2
 
    ; count accepted digit
    ADD     R6, R6, #1
    BRnzp   readLoop
 
checkDone
    ; empty input is invalid
    ADD     R1, R6, #0
    BRz     invalidInput
 
    AND     R0, R0, #0
    ADD     R0, R0, R4
    RET
 
tooManyDigits
    LEA     R0, errTooLong
    PUTS
    BRnzp   MAIN ; restart
 
invalidInput
    LEA     R0, errFormat
    PUTS
    BRnzp   MAIN ; restart
 
;---------------------------------------
; isPrime
; inputs -> R0 = number
; outputs -> R0 = 1 if prime, 0 if not
;---------------------------------------
isPrime
    AND     R1, R1, #0
    AND     R2, R2, #0
    AND     R3, R3, #0
 
    ADD     R2, R2, #-1    ; divisor
 
    ADD     R1, R0, R1
 
    ADD     R1, R1, #-1    ; R0 = 1?
    BRz     isNotPrime
 
    ADD     R1, R1, #-1    ; R0 = 2?
    BRz     isPrimeTrue
    BRp     divisorLoop
 
divisorLoop
    AND     R1, R1, #0
    ADD     R1, R0, R1
 
    ADD     R2, R2, #-1    ; increment divisor
 
    ADD     R1, R1, R2     ; divisor >= n?
    BRz     isPrimeTrue
    BRp     subtractionLoop
 
subtractionLoop
    ADD     R1, R1, R2     ; input - divisor
    BRp     subtractionLoop
    BRz     isNotPrime
    BRn     divisorLoop
 
isPrimeTrue
    AND     R0, R0, #0
    ADD     R0, R0, #1
    RET
 
isNotPrime
    AND     R0, R0, #0
    RET
 
;---------------------------------------
; resultS
; prints whether the number is prime
;---------------------------------------
resultS
    ADD     R0, R0, #0
    BRp     primeMsg
    BRz     notPrimeMsg
 
primeMsg
    LEA     R0, stringPrime
    PUTS
    RET
 
notPrimeMsg
    LEA     R0, stringNotPrime
    PUTS
    RET
 
;---------------------------------------
; prints and data
;---------------------------------------
MSG             .STRINGZ "Input a decimal number (1 to 5 digits): \n"
stringPrime     .STRINGZ "\nThe number is prime \n"
stringNotPrime  .STRINGZ "\nThe number is not prime \n"
errFormat       .STRINGZ "\nError: input must contain digits only (0-9) \n"
errTooLong      .STRINGZ "\nError: input can contain at most 5 digits \n"
ASCII_ZERO      .FILL   x0030
NEWLINE         .FILL   x000A
 
.END
