Group bits in 4s from the right. e.g. 1100 0000 1101 1110 = xC0DE.

2's complement — the whole toolkit

  • Positive → binary: normal binary, pad with leading 0s.
  • Negate (±): invert all bits, then +1. Works both directions.
  • MSB = sign bit. 1 ⇒ negative.
  • Range of n bits: −2^(n−1) … 2^(n−1)−1.
    8 bit: −128…127 · 10 bit: −512…511 · 16 bit: −32768…32767.
  • Sign-extend = copy the MSB left to fill 16 bits.
−127 (8-bit): +127 = 0111 1111 → invert 1000 0000 → +1 = 1000 0001.

Field ranges (all SEXT'd to 16 bit)

4 Condition codes & branching

Every † instruction sets exactly one of N/Z/P from the value written to DR:

  • result < 0 → N=1
  • result = 0 → Z=1
  • result > 0 → P=1

BRn / BRz / BRp / BRnz / BRzp / BRnp / BRnzp(=BR) branch if the matching flag(s) are set.

To test a value, set the flags first. Common idioms:
  • ADD Rx,Rx,#0 → re-test Rx
  • compare to k: ADD Rt,Rx,#-k then BRz (==k) / BRn (<k) / BRp (>k)
  • negate Rx: NOT Rx,Rx + ADD Rx,Rx,#1
  • clear: AND Rx,Rx,#0

5 Assembly ↔ machine code

Assembly → machine code (step by step)

  1. Identify opcode → top 4 bits.
  2. Fill register fields (3 bits each, R0=000 … R7=111).
  3. For immediates/offsets: write the 2's-complement value in the right bit width.
  4. For labels: offset = target_addr − (this_addr + 1), then 2's-complement in 9 or 11 bits.
  5. Group the 16 bits in 4s → hex.

Example: ADD R7, R2, #12

opcode ADD          0001
DR = R7             111
SR1 = R2            010
imm bit             1
imm5 = 12           01100
-------------------------------
0001 1110 1010 1100 = x1EAC

Example: LOOP BRnzp LOOP at x3001

opcode BR            0000
nzp                  111
target  = x3001
PC      = x3002  (this+1)
offset  = 3001-3002 = -1
  → 9-bit:           111111111

0000 1111 1111 1111 = x0FFF

Machine code → assembly

  1. Split top 4 bits → opcode (use the table). 1101 = illegal.
  2. Decode register fields and the addressing-mode bit (bit 5 for ADD/AND).
  3. For offsets, sign-extend and add to (addr+1) to recover the target / label.
Worked (F22): 1110 100 011111111 → opcode 1110 = LEA, DR=R4, off9 = 011111111 = +255 = xFF → LEA R4, x... (R4 ← PC+xFF). Then 0001 010 000 1 00000 → ADD R2,R0,#0 (copy R0→R2), etc.

7 Writing LC-3 programs — reusable patterns

Loop over a string until \0

      LEA R3, S      ; R3 → string
L     LDR R0, R3, #0  ; R0 = current char
      BRz  DONE       ; \0 ends it
      ; ... use R0 ...
      ADD R3, R3, #1  ; next char
      BRnzp L
DONE  HALT
S     .STRINGZ "text"

Counter / accumulator down-loop

      AND R0, R0, #0  ; sum = 0
      LD  R1, N       ; counter
L     BRz  DONE       ; while R1 != 0
      ADD R0, R0, R1
      ADD R1, R1, #-1
      BRnzp L
DONE  HALT
N     .FILL #10
Immediate limit: ADD R0,R0,#37 is illegal — imm5 max is +15. Fixes:
  • Repeat: ADD #15 + ADD #15 + ADD #7
  • Load from memory (handles any size): LD R1, A / ADD R0,R0,R1 / A .FILL #37

Print a number 0–9 as a digit

      LD  R1, ASC0   ; x30
      ADD R0, R3, R1  ; digit + '0'
      OUT
ASC0  .FILL x30

Keep low 4 bits / mask

      AND R1, R2, xF  ; R1 = R2 & 0x000F
; (AND with imm5; xF = 15 fits)
; histogram[idx]++ pattern:
      ADD R1, R1, R4  ; addr = base+idx
      LDR R0, R1, #0
      ADD R0, R0, #1
      STR R0, R1, #0
Typical full program shape: .ORIG x3000 → set up pointers (LEA/LD) → main loop → print results (PUTS strings + OUT digits) → HALT → data (.STRINGZ, .FILL) → .END.

8 Reading assembly as C (and back)

Compiler-generated functions follow a fixed shape. Recognise the prologue / epilogue to skip straight to the logic.

Prologue (function entry)

ADD R6,R6,#-2   ; space for RV + RA
STR R7,R6,#0    ; save return addr
ADD R6,R6,#-1   ; push dynamic link
STR R5,R6,#0    ; (old frame ptr)
ADD R5,R6,#-1   ; R5 → first local
ADD R6,R6,#-k   ; room for k locals

Epilogue (function exit)

STR R0,R5,#3    ; write return value
ADD R6,R5,#1    ; pop locals
LDR R5,R6,#0    ; restore frame ptr
ADD R6,R6,#1
LDR R7,R6,#0    ; restore return addr
ADD R6,R6,#1
RET
Accessing args & locals via R5 (frame pointer): with the layout used here, LDR Rx,R5,#0 reads the first local; positive offsets #4, #5… reach the bookkeeping then the arguments above the frame. Match each LDR/STR Rx,R5,#n to a named variable, translate the arithmetic, then reconstruct the if/while/return.

Example body (F20)

LDR R0,R5,#4   ; x  (1st arg)
LDR R2,R5,#5   ; y  (2nd arg, a ptr)
LDR R1,R2,#0   ; *y
NOT R1,R1 / ADD R1,R1,#1  ; -*y
ADD R0,R0,R1   ; x-*y
ADD R0,R0,#5   ; x-*y+5
STR R0,R5,#0   ; t = ...
BRnz label1    ; if (t>0) ...

Reconstructed C

int func(int x, int* y){
   int t;
   t = x - (*y) + 5;
   if (t > 0)
       return t;
   else
       return 0;
}

BRnz after computing t means "skip the return t when t≤0" → the if(t>0).

9 C — pointers, arrays & strings

  • &x = address of x. *p = value p points to.
  • int* p holds an address; int** t holds the address of a pointer.
  • Array name decays to a pointer to element 0: arr ≡ &arr[0].
  • arr[i] ≡ *(arr+i); arr+2 points at arr[2].
  • Pointer arithmetic steps by element size (here 1 word for int/ptr/char).
  • A string is a char array terminated by '\0'.
Read declarations right-to-left.
  • char* s — pointer to char
  • char** strings — pointer to (pointer to char) = array of strings
  • int* posArray — pointer to int (an int array)
A literal "Hello" lives in read-only memory; p="Hello" just stores its address.

Read a line word-by-word (the canonical fixed version)

char* readString(int* nrWords){
    char c; int i = 0;
    char* buffer = malloc(100*sizeof(char));   // must allocate!
    char wordStarted = 0;
    *nrWords = 0;
    while ((c = getchar()) != '\n'){
        buffer[i++] = c;
        if (c==' ' || c=='\t'){            // == not = , || not &&
            if (wordStarted) wordStarted = 0;
        } else if (!wordStarted){            // new word begins
            wordStarted = 1;
            (*nrWords)++;
        }
    }
    buffer[i] = '\0';
    return buffer;
}

10 C — structs

struct S { char* s; char c; int k; };
struct S  v;     // a struct
struct S* p;     // pointer to struct
  • v.c — member via value.
  • p->c ≡ (*p).c — member via pointer.
  • Size = sum of members (each int/ptr = 1 word, char = 1 word on this LC-3 model).
  • A pointer is always 1 word (16 bit) regardless of what it points to.
Allocate & init a struct on the heap: 
struct S* z = malloc(sizeof(struct S));
z->a = 7;
z->c = malloc(10*sizeof(char));
z->c[0]='O'; z->c[1]='K'; z->c[2]='\0';
On the stack instead: declare the struct as a local and take & of it.

11 C — singly linked lists (the recurring topic)

struct Node { int data; struct Node* next; };

Append at end

void append(Node** head, int v){
   Node* n = malloc(sizeof(Node));
   n->data = v; n->next = NULL;
   if (*head == NULL){ *head = n; return; }
   Node* c = *head;
   while (c->next) c = c->next;
   c->next = n;
}

Push at front

void push(Node** head, int v){
   Node* n = malloc(sizeof(Node));
   n->data = v;
   n->next = *head;
   *head = n;
}

Find middle (slow/fast pointers)

Node* findMiddle(Node* head){
   Node* slow = head; Node* fast = head;
   while (fast && fast->next){
       slow = slow->next;
       fast = fast->next->next;
   }
   return slow;   // 2nd middle if even count
}

Reverse the list

void reverse(){
   Node* cur = header;
   Node* newH = NULL;
   while (cur){
       Node* next = cur->next;
       cur->next = newH;
       newH = cur;
       cur  = next;
   }
   header = newH;
}

Remove duplicates of one node's value

void removeDup(Node* start){
   if (!start) return;
   Node* prev = start;
   Node* cur  = start->next;
   while (cur){
       if (cur->data == start->data)
           prev->next = cur->next;   // unlink
       else
           prev = cur;
       cur = cur->next;
   }
}
// remove ALL dups: call removeDup(c) for each node c
Why Node** (pointer-to-pointer)? When a function must change where the caller's head points (e.g. push/append into an empty list), it needs the address of the head pointer. Walking/printing only reads, so Node* is enough.

13 Runtime stack / activation record

This is the highest-yield topic. The stack grows downward (toward lower addresses). When empty, R6 holds the given top value (e.g. xFFFF or xFE00); the empty value itself is never written to — the first push goes one below it.

Layout convention (top → bottom)

…+3Return Value (RV)
…+2Return Address (RA)
…+1Dynamic Link (DL = old R5)
R5→first local (highest word)
…locals, in declaration order, going down
R6→last local (lowest word)

DL / RA / RV = "bookkeeping" = 3 words per frame (when there's no return value some treat it as still reserved — match the worked solutions: 3 words).

Build-it checklist

  1. Start from the empty R6 value at the very top.
  2. If a function was called with arguments, those sit above the callee's bookkeeping, pushed right-to-left (last arg lowest).
  3. Write bookkeeping: RV, RA, DL (top→down).
  4. Place locals in declaration order, each new variable just below the previous.
  5. For arrays/structs: the block sits below the previous var, with index 0 / first member at the lowest address, last element adjacent to the variable above.
  6. Each int / pointer / char / struct-member = 1 word.

arr[0] is at the bottom of arr's block (FDF9), arr[3] adjacent to DL — so the array reads "upward". Same rule for s1.c below s1.v.
Nested frames (caller + callee, e.g. F20): draw main's frame at the top, then the argument(s) of the called function, then the called function's RV/RA/DL, then its locals — all continuing downward. The argument *x stored in the callee's frame contains the address passed in (e.g. &t pointing back up into main's frame).

14 Pointer-tracing walkthrough

For "show the activation record before return" and "what is the output" questions: build the frame first, then execute each statement and update values, keeping a running note of what every pointer currently points at.

Example (F24 body)

int arr[]={22,33,11,25};  s1; ps; pps; int d=7;
pps = &ps;            // pps → ps
ps  = &s1;            // ps  → s1   (so *pps == ps)
(*pps)->v = arr+2;    // s1.v → arr[2]   (addr FDFB)
(*(ps->v))++;         // arr[2]: 11 → 12
s1.v = s1.v + 1;      // s1.v → arr[3]
(*(ps->v))++;         // arr[3]: 25 → 26
(*ps).c = 'D';        // s1.c = 'D'
(*pps)->v = &d;       // s1.v → d
*((*pps)->v) = 5;     // d: 7 → 5
(*pps)->c = 'a';      // s1.c = 'a'
d++;                  // d: 5 → 6   (s1.v still → d)
Resulting output: 
arr = {22, 33, 12, 26}
s1.c = a
*(s1.v) = 6
s1.v points at d, and d is now 6.
Method that prevents mistakes:
  1. Resolve the pointer chain on the left first: (*pps)->v ⇒ "pps points to ps, ps points to s1, so this is s1.v".
  2. Resolve the right to a concrete value/address.
  3. Apply ++/-- to whatever the dereference finally lands on — a stored value, not the pointer, when it's *(...)++ grouped as (*(...))++.
  4. Update the table, note which variable each pointer now targets.
Watch the parentheses. (*(ps->v))++ increments the int that v points at. (ps->v)++ would instead move the pointer. And s1.v = s1.v + 1 advances the pointer by one element (one word here). Track "pointer moved" vs "value changed" separately.
