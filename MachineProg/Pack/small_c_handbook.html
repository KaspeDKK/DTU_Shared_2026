1 What Small-C is, and why it matters here

Small-C is a deliberately tiny subset of C with a single-pass compiler small enough to read end-to-end. The course uses it because you can see exactly what assembly each C construct turns into — which is the whole point of the activation-record and "translate this function" exam questions.

Original Small-C has only…

  • Two data types: int and char (plus pointers to and arrays of them).
  • One-dimensional arrays and single-level... well, full pointers.
  • Functions returning int (everything is int-sized unless it's a char).
  • Global and local (automatic) variables — no nested scopes beyond function bodies.
The exam uses fuller C. Past papers freely use struct, malloc/free, for, unsigned int, '\t', multi-file headers, etc. Treat Small-C as the model of how compilation works, and standard C as the language you actually write. Items only in standard C are tagged std C below.
On the LC-3 model the course adapts the same stack-machine idea: every int, char, pointer and struct member occupies 1 word (16 bit), memory is word-addressable, locals go on the runtime stack in declaration order, and arguments are pushed right-to-left. Keep that mapping in mind throughout.

2 Program structure

A C program is a flat list of external declarations: global variables and functions. Execution begins at main. There is no code outside functions; a string literal or global array just reserves data.

/* globals: visible to every function below */
int values[] = {3,5,3,5,8,4};
int count;

int helper(int x){ return x + 1; }   /* a function */

int main(){
    count = helper(values[0]);
    return 0;
}
  • Declaration vs definition: a prototype like void f(int); declares; the body defines. Globals declared before use; functions may be forward-declared.
  • Scope: a name is visible from its declaration to the end of its block. Globals live for the whole run; locals live only while their function is active.
  • Statements end with ;; blocks group with { }.

On a desktop GCC int is usually 4 bytes — but for every LC-3/stack question in this course treat it as 1 word.

Constants & literals

  • Integer: 42 (decimal), 0x2A (hex), 052 (octal).
  • Character: 'A' = the ASCII value 65. Escapes: '\n'=10, '\t'=9, '\0'=0, '\\', '\''.
  • String: "Hi" is a char array {'H','i','\0'}; its value in an expression is the address of the first char.
  • A constant expression like 123+321 is folded by the compiler into a single value.
ASCII you actually need: '0'=48 (x30) … '9'=57 (x39); 'A'=65 (x41); 'a'=97 (x61); space=32 (x20). Digit→value: subtract '0'. Lower→upper: subtract 32 (0x20).

4 Variables & declarations

  • Global variables are stored at fixed addresses; they keep their value for the whole program and default to 0 if not initialised.
  • Local (automatic) variables live on the runtime stack, exist only while the function runs, and start with garbage unless you initialise them. Forgetting to initialise a local index/counter is a classic exam bug.

5 Pointers

A pointer holds a memory address. On LC-3 it is one 16-bit word no matter what it points to.

The two core operators

  • &x — address of x.
  • *p — value at the address in p (dereference). * and & are inverses: *(&x) == x.
int  x = 7;
int* p = &x;   // p points to x
*p = 9;        // now x == 9
int** t = &p;  // t points to p
**t = 4;       // *t is p, **t is x → x = 4

Pointer arithmetic

  • p + 1 advances by one element (here 1 word), not one byte.
  • p++ moves the pointer; (*p)++ changes the value it points at. Parentheses decide which.
  • p - q = number of elements between them.
  • NULL (= 0) means "points nowhere"; test before dereferencing.
Passing by pointer is how a function changes the caller's variable. void inc(int* n){ (*n)++; } then inc(&x) changes x. C is otherwise pass-by-value.

6 Arrays & strings

Array ≈ pointer

  • An array name used in an expression decays to a pointer to element 0: a ≡ &a[0].
  • a[i] is defined as *(a + i) — so a[2], *(a+2), and 2[a] all mean the same.
  • The elements are contiguous in memory, index 0 at the lowest address.
  • Difference from a pointer: an array name is not a modifiable lvalue — you can't reassign a, but you can reassign a p that points into it.

Strings

  • A C string is a char array ending in '\0'.
  • String functions loop until they hit the terminator.
  • char* s = "Hi"; stores the address of a read-only literal. char s[] = "Hi"; makes a writable local copy (3 chars incl. \0).
// length of a C string
int len(char* s){
    int n = 0;
    while (*s++ != '\0') n++;
    return n;
}
Indexing past the end (or writing through a pointer you never pointed at real storage) corrupts memory silently. Always allocate before you write: char* buf = malloc(100); std C — never char* buf; then buf[0]=….

7 Initial values

  • Scalars: int i = 5;
  • Arrays: int a[4] = {22,33,11,25}; If fewer initialisers than elements, the rest are 0. int a[] = {1,2,3}; sizes itself to 3.
  • Char arrays from strings: char s[] = "Text"; = {'T','e','x','t','\0'} → 5 words.
  • Structs std C: struct S a = {5, 'z', ptr}; fills members in order.
Globals vs locals: uninitialised globals are guaranteed 0; uninitialised locals are undefined. When drawing a stack frame "before return", a local you never wrote still occupies its word — its value is "?" until the code assigns it.

8 Functions & the calling convention

This is the heart of the exam. A function call sets up a fresh activation record (stack frame) and tears it down on return.

The contract (course / Small-C model)

  1. Caller evaluates arguments and pushes them onto the stack right-to-left (so the first argument ends up at the lowest-numbered argument slot, nearest the callee).
  2. The call saves the return address.
  3. Callee saves the old frame pointer (dynamic link), sets its own frame pointer, and allocates space for its locals (declaration order, growing downward).
  4. On return, the callee writes the return value, deallocates locals, restores the frame pointer and return address, and jumps back.
  5. Caller removes the arguments it pushed.
Why right-to-left & why a frame pointer? Right-to-left push lets the first parameter sit at a fixed, known offset even when the count varies. A dedicated frame pointer (R5 on LC-3) gives every local and argument a constant offset regardless of how much the stack pointer (R6) moves during expression evaluation.

Recognising the LC-3 prologue / epilogue

; --- prologue ---
ADD R6,R6,#-2  ; reserve RV + RA
STR R7,R6,#0   ; save return address
ADD R6,R6,#-1  ; push dynamic link
STR R5,R6,#0   ; (old frame ptr)
ADD R5,R6,#-1  ; R5 -> first local
ADD R6,R6,#-k  ; room for k locals
; --- epilogue ---
STR R0,R5,#3   ; store return value
ADD R6,R5,#1   ; pop locals
LDR R5,R6,#0   ; restore frame ptr
ADD R6,R6,#1
LDR R7,R6,#0   ; restore return addr
ADD R6,R6,#1
RET
Accessing args & locals: with R5 at the first local, LDR Rx,R5,#0 reads local 0; positive offsets reach over the bookkeeping to the arguments (e.g. #4, #5 for the 1st, 2nd argument in the course's layout). Match each LDR/STR ...,R5,#n to a named variable, then translate the arithmetic between them.

Things that trip people up

  • *p++ = *(p++): read *p, then advance p. To change the value, write (*p)++.
  • a && b short-circuits: if a is false, b is never evaluated. Used for safe checks like while (p && p->next).
  • Integer division truncates: 7/2 == 3. % is the remainder: 7%2 == 1, x%8==0 tests "multiple of 8".
  • Bitwise & vs logical && are different operators — mixing them is a frequent bug.
  • Assignment = returns the assigned value, so if (c = ' ') compiles but is almost always a mistyped ==.
Member access: s.m for a struct value, p->m for a struct pointer (≡ (*p).m). Chains resolve left-to-right: (*pps)->v = "follow pps to a struct pointer, then take its v member".

11 The code-generation model

The compiler views the CPU as a tiny stack machine with one main working register (the primary, the accumulator for expression results) and a secondary register for the left operand of a binary operation. The runtime stack does the rest.

Evaluating an expression

  1. Compute the left operand into the primary register; push it.
  2. Compute the right operand into the primary register.
  3. Pop the saved left operand into the secondary register.
  4. Apply the operator → result in the primary register.

Nested sub-expressions recurse the same way, which is why the stack pointer moves around during a statement — and why a stable frame pointer is needed to find variables.

Two kinds of value. A variable reference can produce either its address (an lvalue, needed on the left of = or for &) or its contents (an rvalue). x = x + 1 uses x as an address on the left and as a value on the right. Tracking "address vs value" is exactly what the pointer-trace questions test.

How each declaration is laid down

  • Global int → one word of data (a .FILL-style cell). Global char → one word too (on LC-3, word-addressable).
  • Global array → a contiguous block; missing initialisers are zero.
  • String literal → a null-terminated char block placed with the function's data; its value is the block's address.
  • Local → space carved from the stack in the prologue, addressed as an offset from the frame pointer.

12 The activation record (drawing it)

The stack grows downward (toward smaller addresses). The "empty" R6 value sits at the very top and is never written; the first push goes one word below it.

One frame, top → bottom

highReturn Value (RV)
↑Return Address (RA)
 Dynamic Link (DL = old FP)
R5→local #1 (declared first)
 local #2 …
R6→last local (lowest word)

RV / RA / DL = "bookkeeping" = 3 words per frame in the course's solutions.

Build-it checklist

  1. Start from the empty R6 value at the top (e.g. xFFFF or xFE00).
  2. If the function was called with arguments, they sit above the callee's bookkeeping, pushed right-to-left (last arg at the lowest of them).
  3. Write the 3 bookkeeping words: RV, RA, DL.
  4. Place locals in declaration order, each new variable one word below the previous.
  5. For an array/struct, the block sits below the prior variable with index 0 / first member at the lowest address (so it reads "upward").
  6. Every int, char, pointer, and struct member = 1 word.

13 C → stack mapping & pointer tracing

For "what is the output / show the record before return" questions, build the frame, then execute each line updating values and noting where each pointer points.

Method that prevents mistakes

  1. Resolve the left side's pointer chain to a concrete variable: (*pps)->v → "pps points to ps, ps points to s1, so this is s1.v".
  2. Resolve the right side to a concrete value or address.
  3. Apply ++/-- to whatever the dereference lands on. (*(p))++ changes a stored value; p++ or p = p+1 moves the pointer by one element.
  4. Update the table and re-note each pointer's target.
int arr[]={22,33,11,25}; s1; ps; pps; int d=7;
pps = &ps;          // pps→ps
ps  = &s1;          // ps→s1  (so *pps==ps)
(*pps)->v = arr+2;  // s1.v→arr[2]
(*(ps->v))++;       // arr[2]: 11→12
s1.v = s1.v + 1;    // s1.v→arr[3]
(*(ps->v))++;       // arr[3]: 25→26
(*ps).c = 'D';      // s1.c='D'
(*pps)->v = &d;     // s1.v→d
*((*pps)->v) = 5;   // d: 7→5
(*pps)->c = 'a';    // s1.c='a'
d++;                // d: 5→6 (s1.v still→d)
Output: 
arr = {22, 33, 12, 26}
s1.c = a
*(s1.v) = 6
s1.v points at d, which is now 6.
Watch parentheses: (*(ps->v))++ increments the int that v points at; (ps->v)++ would move the pointer instead.

Read a line, count words

char* readString(int* nrWords){
   char c; int i = 0;
   char* buf = malloc(100);  // allocate!
   char inWord = 0;
   *nrWords = 0;
   while ((c=getchar()) != '\n'){
      buf[i++] = c;
      if (c==' ' || c=='\t')   // == and ||
         inWord = 0;
      else if (!inWord){
         inWord = 1; (*nrWords)++;
      }
   }
   buf[i] = '\0';            // terminate
   return buf;
}

Linked-list essentials std C

struct Node{ int data; struct Node* next; };

// push at front (needs Node** to change head)
void push(Node** head, int v){
   Node* n = malloc(sizeof(Node));
   n->data = v; n->next = *head; *head = n;
}
// reverse
void reverse(){
   Node* cur=header, *nh=NULL, *nx;
   while(cur){ nx=cur->next; cur->next=nh;
              nh=cur; cur=nx; }
   header=nh;
}
